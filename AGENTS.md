# AGENTS.md

Rules for AI agents in this repository. They override default agent behaviour.

UI and component rules live in `web/AGENTS.md`, generated by the Astryx CLI. Read it before writing any UI. Do not edit it by hand; regenerate it after an Astryx upgrade.

---

## 1. Never commit

Only a human commits here.

**Forbidden:** `git commit`, `push`, `merge`, `rebase`, `reset --hard`, `clean`, `tag`, `revert`, `config`, and creating pull requests.
**Allowed:** `git add`, `status`, `diff`, `log`, and editing files.

Workflow: change files, `git add` them, report what changed, print a proposed commit message in a code block, stop.

If you are asked to commit, state this rule and print the message instead. This holds even when the change is small or the task looks finished.

---

## 2. Report in simplified technical English

- One idea per sentence. Common words. No idioms, no filler, no praise.
- Result first, then detail.
- Use exact names: `web/tsconfig.json`, not "the config".
- Use a table or bullets for more than three items.
- Say what failed. Never hide an error inside a summary.
- Mark anything you did not verify as "unverified".
- Never claim something works unless you ran it and saw the result.
- Give numbers. "4,978 sections" beats "many sections".

Bad: "Great news — the scraper is humming along and the data looks fantastic!"
Good: "The scraper pulled 4,978 sections from 96 subjects. No requests failed."

---

## 3. Code style

Small functions that do one thing. Names that say what the thing is. No dead code, no commented-out code. Comments explain **why**. Handle every error path.

**Formatters are authoritative. Never hand-format, and never fight the formatter.**

| Language | Format | Lint — must report zero warnings |
|---|---|---|
| Rust | `cargo fmt` | `cargo clippy --all-targets -- -D warnings` |
| TypeScript, from `web/` | `npm run format` | `npm run lint` |

**Rust** follows the official Rust style guide. Google publishes none. No `unwrap()` or `expect()` in library code; return `Result`. Model invalid states as enums so they cannot be built. Document public items with `///`. Keep `skyspace-core` pure: no I/O, no `async`.

**TypeScript** follows the Google TypeScript Style Guide, enforced by gts. No `any`. Named exports only. Explicit return types on exported functions. Function components only.

Three gts facts you must not "fix":

- `web/eslint.config.mjs` imports `gts/build/eslint.config.js`. The package's root config requires a file it does not publish.
- Our config repoints `parserOptions.project` at `web/tsconfig.json`, because gts points at a tsconfig it does not ship.
- Never run `npx gts init`. It overwrites `tsconfig.json` and the package scripts, and breaks the Vite build.

## 4. Project rules

**Data**

- Public Rice pages only: `courses.rice.edu` and `ga.rice.edu`. Never Esther. Never request, store, or type a NetID password.
- Space requests at least 150 ms apart. Cache responses. Identify the client in the User-Agent.
- Never commit pulled data. State which page you fetched, and when.
- Requirement extraction produces a **draft**. A person who knows the program reviews it before it affects a student's plan.

**Product**

- The plan is the student's document. The application warns; it never blocks.
- Any rule the engine cannot verify becomes a visible self-check, never a silent omission.

**Repository**

- A tracked file must never point at a gitignored path. `docs/` is ignored, so a link to it from `AGENTS.md`, `README.md` or source code is broken in every fresh clone.
